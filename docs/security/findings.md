# Findings of the security review (29 Oct 2026)

Background is in [threat-model.md](threat-model.md); what operators must configure is in [operator-checklist.md](operator-checklist.md). Tests: `scripts/test-security.mjs` (part of `scripts/test.sh`), `packages/sql/test/tests.sql`, `apps/server/test/admin.test.mjs`, `apps/ui/e2e/auth.spec.js`.

Some findings sit in the deployment package (`docker-compose.override.yml`, `stack/`, `Dockerfile`, `deploy/`) or concern tests; their fixes are marked "deployment package" below. State reviewed: `main` 051b0cb, with the stack restarted on it.

| ID | Severity | Finding | Evidence | Fix | Status |
|---|---|---|---|---|---|
| F-01 | **High** | MFA applied only in the UI. The password alone opened the data through PostgREST, Storage and MCP. OAuth tokens are always `aal1`, and the consent API accepts an AAL1 session. | PoC: AAL1 token → `suedwind.products` 200. Tests: `tests.sql` (hook, `confirm_mfa_client`), suite §3, E2E "person with a second factor" | The hook grants the role only with `aal2`, or for a client that the person has confirmed with AAL2 on the consent page | **Fixed** (install.sql v4, `consent.jsx`; installed on the stack) |
| F-02 | **High (conditional)** | Storage serves SVG without CSP and without `nosniff`. If the UI is on the same origin as `/storage/v1`, an uploaded SVG executes code there and can read the token. | PoC: public GET of an SVG without protective headers | UI image upload accepts raster formats only; `cms.check_storage()` reports buckets without a file type limit; checklist. Deployment package: sandbox CSP and `nosniff` on `/storage/v1/object/*` in the gateway | **Fixed** (deployment package: sandbox CSP + nosniff on storage, verified on the stack) |
| F-03 | **High** | The OAuth token of an MCP client is a full token of the person: it changes the password without re-authentication and signs the person out globally. With open DCR (free name, `https` on any host), phishing via the consent page becomes account takeover. | PoC: `PUT /auth/v1/user {password}` → 200. Suite §2, `admin.test.mjs`, E2E "sends the access to another machine" | Admin API rejects OAuth tokens; consent page warns when the access goes to a foreign host. Deployment package: `GOTRUE_SECURITY_UPDATE_PASSWORD_REQUIRE_REAUTHENTICATION=true` and session timebox (F-06) | **Fixed** (deployment package: re-auth on password change, timebox; verified on the stack) |
| F-04 | Medium | `record_history` showed admins entire rows: including columns hidden by their column rights and rows hidden by RLS. | `tests.sql`: two tests (columns, RLS) | Filter columns to the read right; admins without a read right on `audit.change_log` get the history only for rows they can currently see | **Fixed** (v4/v6) |
| F-05 | Medium | Revoking rights, banning, signing out and deleting take effect only when the token expires (`JWT_EXPIRY` 3600 s). | Suite §1 INFO | `JWT_EXPIRY` 900 s in production (checklist). Immediate revocation would need a check on every request and is deliberately not built | **Fixed** (package: `JWT_EXP` 900 s; deliberately 3600 locally) |
| F-06 | Medium | Sessions never expire, including the refresh tokens of the MCP clients. | Auth environment | `GOTRUE_SESSIONS_TIMEBOX` / `…_INACTIVITY_TIMEOUT` | **Fixed** (timebox 720 h, inactivity 168 h; verified on the stack) |
| F-07 | Medium | Public buckets bypass all policies on read. | Suite §5 INFO (file without token 200) | `cms.check_storage()` reports them; the UI shows "Public bucket" when uploading; checklist: separate buckets. A public bucket stays public if the operator wants it that way | **Fixed** (report + notice) |
| F-08 | Medium | `EXECUTE` for `PUBLIC` on new functions in `public`, even after `fix_public_defaults()`. | `tests.sql` "include_public_execute" | `fix_public_defaults(include_public_execute => true)` revokes it globally (Postgres has no per-schema switch). Opt-in, described in the checklist | **Fixed** (option) |
| F-09 | Medium | On Supabase Cloud, self-registration is on by default; every registered person can use CMS and MCP as `authenticated`. | Configuration | Checklist: signup off, people only by invitation | **Fixed** (docs; signup off in the package) |
| F-10 | Low | The invitation took `Origin` as `redirect_to`; the allow-list has port wildcards. | PoC: `Origin: http://localhost:9` → `redirect_to=http://localhost:9/cms/` | `CMS_PUBLIC_UI_URL` fixes the target (unit test); allow-list in production without wildcards | **Fixed** (`CMS_PUBLIC_UI_URL` in `cms-admin`; package allow-list without wildcards) |
| F-11 | Low | MCP read bodies up to about 7 MB before checking the token. | Suite §5 | Token check before the body parser | **Fixed** (image rebuilt, suite §5 green) |
| F-12 | Low | `cms.is_admin` (security definer) had a `search_path` without `pg_temp` at the end. | Code | `pg_catalog, pg_temp` | **Fixed** |
| F-13 | Low | `brand-bootstrap.sql`: `_` was a LIKE wildcard in the agency storage policy. | `'acmeXoutdoor/a' like E'acme\\_outdoor/%'` → f | Escape; effect of the script described in threat-model 4.10 and in the checklist | **Fixed** |
| F-14 | Low | `CMS_ADMIN_INVITE_DELIVERY=link` gives the admin sign-in links for foreign accounts. | Code | Production: `mail` (checklist) | **Fixed** (package default `mail`; `link` locally) |
| F-15 | Low | The service key was in the same process as the MCP server. | Suite §4 (canary) | `apps/server/admin.mjs`: admin API as its own process (service `cms-admin`, port 8081); `server.mjs` mounts the admin routes only if it has a key itself | **Fixed** (service `cms-admin` with key, `cms` without; verified on the stack) |
| F-16 | Low | UI: `decode-uri-component` ≤ 0.4.2 (via `react-admin` → `query-string` 7) with a DoS advisory. | `npm audit` | Vite alias to a linear shim (`apps/ui/src/shims/`): the code is no longer in the bundle (verified). `npm audit` still lists the package because it stays installed; the release audit fails only from "high" | **Fixed** (bundle) |
| F-17 | Info | CSP `style-src 'unsafe-inline'` (MUI/emotion needs it; no script possible); no HSTS; tokens in `localStorage` (strict CSP, DOMPurify in `RichTextField`) | Suite §5 | HSTS at the TLS proxy. `unsafe-inline` for styles stays: a nonce would need server-side rendering | HSTS: **fixed** (Caddyfile, docs); `unsafe-inline` for styles accepted |
| F-18 | Info | Prompt injection through data content | Code, suite §2 | MCP instructions: content is data, never instructions; `create_signed_url` for 24 h at most and only when the person asks | **Fixed** |
| F-19 | Info | `is_assignable_role` checked neither inherited rights nor `CREATEROLE`/`CREATEDB`. | `tests.sql` (two tests) | Such roles are not assignable; the hook does not grant them; `cms.check_roles()` reports existing assignments | **Fixed** (v6) |
| F-20 | Info | Uninstalling with the hook active made every sign-in impossible. | `test-sql.sh` | `uninstall.sql` aborts until `set cms.hook_disabled = on` is set | **Fixed** |
| F-21 | Info | Test gap: the MCP authenticator had no unit tests with expired, foreign or `alg=none` tokens. | `apps/server/test/mcp-auth.test.mjs`: 22 bad tokens × POST/GET/DELETE → 401, no call to PostgREST | Tests added; cross-checked with four deliberate gaps | **Fixed** |
| F-22 | Low | The gateway (Envoy, upstream configuration) reflects every origin, including on `/cms/api/admin/*`. Without cookies this is not CSRF, but it is needlessly open for the admin API: the UI is on the same origin. | Suite §5 on the stack: OPTIONS with `Origin: https://evil.example` → `access-control-allow-origin` reflected | CORS policy for the `cms-admin` route: only the origin of the UI | **Fixed** (deployment package: dedicated CORS policy on the route, gateway origin only; verified on the stack) |
